Image Processing

Topics

Digital images and photography

Prerequisites Concepts

parallel loops (or GPU kernels), metering, speedup, computational efficiency

Instructions

Images can be processed by modifying the RGB values of individual pixels to achieve effects such as inverting the colors of an image. Since many image processing operations can treat each pixel independently, this work is well-suited for parallelization. By processing multiple pixels simultaneously across different threads, we can achieve significant speedups over sequential processing. This project involves implementing various image processing algorithms and using multithreading to accelerate image transformations.

The program uses a graphics library developed here at Calvin University called the Thread-Safe Graphics Library, aka TSGL. Other graphics libraries are not thread-safe, meaning if two threads try to perform graphical calls at the same time, the program will likely crash. To support multithreaded graphical programming, we developed TSGL, which lets different threads safely perform simultaneous graphics calls in approximately real-time.

The assignment is:
  1. Starting with one of the sequential programs provided below, add internal timing calls (e.g., using OpenMP's Wtime functions) to the beginning and end of the sequential program to measure precisely how long it takes to solve the problem. Record that time in a spreadsheet, indicating that it is the time to solve the problem using 1 processing element (PE).
  2. Use parallel techniques to convert the sequential program into a parallel program that solves the problem. (Hint: Convert the for loop into a parallel loop.)
  3. In your spreadsheet, record the raw times your parallel solution requires to solve the problem using a given number of PEs. For each PE value, calculate the speedup and computational efficiency. Then create three well-labelled line-charts that (respectively) show the relationship between the number of PEs and:
    1. the raw times,
    2. the speedup values, and
    3. the computational efficiency values.
    Each chart should plot the number of PEs on the horizontal axis and the other value (time, speedup, efficiency) on the vertical axis. Depending on which parallel software option you are using (see below), your instructor may provide additional details regarding their precise expectations, such as the number of PEs you are to use.
  4. Write a 1-page report in which you explain what your charts reveal about the relationships between the number of PEs and the raw time, the speedup, and the computational efficiency of your parallel program.

Deliverables

Using the submission process at your institution, turn in:
  1. Your 1-page report.
  2. Your three charts (one per page, landscape, maximized to fill the page).
  3. Your spreadsheet, showing the data used to generate your charts.
  4. The source code of your parallel program.
